# ZONEFALL — ブラウザ・バトルロイヤル

飛行機から降下し、島で武器と装備を集め、縮小する安全地帯の中で最後の一人を目指す、ブラウザ向けバトルロイヤルゲームです。
three.js などのエンジンは使わず、**Rust → WebAssembly** のシミュレーションと **素の WebGPU (WGSL)** レンダラで作っています。

- **遊ぶ (GitHub Pages)**: https://github30.github.io/knives-out/
- **遊ぶ (Cloudflare ミラー)**: https://zonefall-server.6u.workers.dev/

> ジャンルとしてのバトルロイヤル（荒野行動のような降下・物資・安全地帯・最後の一人）を参考にした、オリジナルのゲームです。名称・マップ・キャラクター・アートはすべて独自のものです。

## 特徴

| | |
|---|---|
| モード | ソロ（ボット戦・オフライン）／オンライン公開マッチ／ルームコードでフレンド戦 |
| 人数 | 最大 30 人（足りない枠はボットが参加） |
| マップ | 1 km 四方の手続き生成の島。町・工業地帯・軍事基地・小屋・森・岩・道路・海 |
| 流れ | 飛行機 → 自由降下 → パラシュート → 物資集め → 6 段階で縮小する安全地帯 |
| 武器 | ハンドガン / SMG / アサルトライフル / ショットガン / マークスマン / スナイパー / 素手 / グレネード |
| 装備 | ベスト・ヘルメット (Lv1〜3, 耐久値) / 包帯・救急キット・エナジードリンク |
| 描画 | WebGPU: シャドウマップ, MSAA, フォグ, 水面 (海底の深度で色が変化), 空と雲, 安全地帯の壁, 揺れる木々, パーティクル |
| 操作 | PC（マウス + キーボード、ポインタロック）とスマホ用タッチ UI |

### スマホ操作
- 画面左：フローティング移動スティック（上に大きく引いて離すとオートラン）
- 画面右：スワイプで視点移動
- 射撃ボタンは左右に 2 つ。押したままドラッグで照準可能
- スコープ / ジャンプ / しゃがみ / リロード / 回復 / グレネード / 拾う / マップ ボタン
- 設定で「オート射撃」（照準に敵が重なると自動射撃）
- 縦持ち時は横向きを促すオーバーレイ、可能な端末ではフルスクリーン + 横向きロック

## アーキテクチャ

```
core/          Rust (no dependencies) → wasm32-unknown-unknown, ~260 KB
  world.rs     島の地形・町・建物・木・岩・物資スポーンの決定的生成, 衝突判定とレイキャスト
  player.rs    移動・降下・パラシュート (サーバーとクライアント予測で共通のコード)
  sim.rs       権威サーバーの試合ロジック: 射撃 (ラグ補償), ダメージ, アイテム, 安全地帯, 飛行機, バイナリプロトコル
  bot.rs       ボット AI (降下先選択, 物資漁り, 建物のドア経由の経路, 索敵, 戦闘, 安全地帯への移動)
  mesh.rs      描画用メッシュ (地形・建物・植生) とミニマップ画像の生成
src/           TypeScript クライアント (Vite)
  render/      WebGPU レンダラ, WGSL シェーダ, ボックスモデル (キャラクター・銃・アイテム・飛行機)
  game.ts      クライアント予測と再照合, 補間, カメラ, エフェクト, イベント処理
  sim-worker.ts オフライン時は Web Worker 内で同じ Rust サーバーを動かす
  touch.ts     モバイル操作 UI
server/        Cloudflare Worker + Durable Objects
  Lobby DO     公開マッチの部屋割り, 接続数・部屋数の上限
  Room DO      1 試合 = 1 Durable Object。同じ core.wasm を 30 Hz で実行し WebSocket で配信
```

同じ `core.wasm` が **ブラウザ (描画用メッシュ・予測)**, **Web Worker (オフラインサーバー)**, **Durable Object (オンラインサーバー)** の 3 か所で動きます。
ワールドはシードから決定的に生成されるため、サーバーはシードとチェックサムだけを送り、クライアントは同一の島を手元で生成します。

ネットコードは Quake/Source 系の構成です：入力コマンド (30 Hz) をサーバーがプレイヤーごとのキューに入れて 1 tick ずつ処理、自分はクライアント側で同じ Rust の移動コードで予測→スナップショットで再照合、他プレイヤーは補間表示、射撃はサーバー側で最大 500 ms 巻き戻すラグ補償です。

## セキュリティと敵対的レビュー

複数のレビュー担当エージェントによる敵対的レビュー（攻撃側の実証コード付き）を 5 ラウンド行い（2 ラウンド目以降は前回の修正の再検証と新しい攻撃の探索）、見つかった問題を修正しました。主な対策：

| 分類 | 対策 |
|---|---|
| 速度ハック・ホバー | プレイヤーごとの「ラグ会計」。シミュレーションした歩数は常に「経過 tick − 4」〜「経過 tick」の範囲に収まり、送信タイミングをどう操作しても速く走ったり空中に留まったりできない。3 tick を超える入力遅延は空ステップで埋め、後から届いた分は破棄（タップ入力は引き継ぐ）。回線の遅延が下がった後などに溜まったコマンドは間引き、入力遅延を元に戻す |
| 回線停止時の予測 | 空ステップで代わりに処理したコマンド数（約 8 秒分まで）をスナップショットで通知し、クライアントはそのコマンドを再生しない（上り回線が 0.4〜2.5 秒止まっても降下中の位置補正は 3 m 未満、停止後に入力遅延も残らない）。遅延の推定には直近 3 回の ping の中央値を使い、停止中に遅れた ping に引きずられない。停止後に届くまとまったコマンドも約 8 秒分まで受け付ける |
| ラグ補償の悪用 | 巻き戻しは記録済みの tick のみ・最大 15 tick (500 ms)。直近の巻き戻し量 +4 tick までに制限し、低遅延のクライアントが 1 発だけ大きく巻き戻すことを防止。巻き戻し量は常に「下限〜下限 +4 tick」の範囲で、下限は 1 コマンドあたり最大 1 tick しか下がらない（15 tick の弾の直後に 1 tick の弾を撃ち分けることはできない）。サーバー時刻より先の視点を申告したコマンドや、サーバーの処理落ちからの追いつき中のコマンドは下限を動かさない。※クライアントが申告する遅延そのものはサーバーでは検証できないため、500 ms 以内の巻き戻しは一般的なゲームと同様に許容 |
| 当たり判定 | 頭と胴体の判定を描画モデルに一致させる（前傾・視線の上下・しゃがみ・ダッシュ・降下中の姿勢）。巻き戻した相手はクライアントが実際に描いた姿（スナップショット間の補間と新しい側の姿勢。向きと視線はクライアントと同じ倍精度の計算、見えたばかりの相手は補間なし）で判定するため、スナップショットの間だけしゃがむ・半回転する等で頭を外させることはできない。頭か胴かは描画された胴体・腕・銃・救急キットを頭より先に通るかで判定し、下から顎を狙った弾や降下中の頭も頭として扱う。ダッシュ姿勢は位置の変化から判定（壁に向かって走り続けても前傾扱いにならない） |
| 壁抜け | 射撃の起点は肩カメラの線上でも壁の手前にクランプ、遮蔽判定は目から。グレネード・近接攻撃・アイテム取得も壁越し不可。窓の敷居での空中ジャンプや天井への立ち上がりによる押し出しを修正 |
| ウォールハック / レーダー | 他プレイヤーは視線が通る相手だけ送信。見えない相手の物資取得・発射者 ID・グレネード・降下着地は送らない。見えない相手の銃声は世界座標に固定した 8 / 16 / 32 m の格子の中心だけ（外れ弾と、射手の近くの壁や自分から見えない位置への着弾は方向のみ）、見えない被弾者の着弾点は送らず、被弾方向表示も 32 方位の方向のみ。アイテムの変化は新しい状態だけを順序どおり送り、チャンクの再同期は自分の変化では起きず、時刻も変化ごとにサーバーの秘密値でずらす（自分の操作で引き直せない）。アイテム ID も秘密の並べ替えで送り、作成順から時刻を読めない。体力は観戦中の相手のみ。※見える射手の弾道（向きと壁への着弾）は、隠れた標的がその線上にいることを示しうる（射手の向きから誰でも分かる情報のため許容） |
| 予測可能な乱数 | サーバー側 128 bit の乱数で試合を初期化。射撃の拡散は別系統の乱数 |
| なりすまし名 | 名前は許可リスト方式（不可視文字・書式制御文字・点字の空白・部首や互換漢字・ローマ数字・正規化で別の文字になる文字を除去、結合文字は 1 文字あたり 2 個まで、絵文字の結合は絵文字の間のみ）。重複判定ではアクセント（合成済み・分解形）・互換文字（µ / μ, … / ...）・大文字小文字・全角半角・濁点・ギリシャ / キリル / アルメニア / ヘブライ / アラビア文字の似た文字・ギリシャ文字とキリル文字の同形（П / Π, Г / Γ, Ө / Θ）・数字の 3 とキリル文字の З・カタカナに似た漢字やひらがな、ハングル字母（力 / カ, 一 / ー / ㅡ, へ / ヘ）・各種ダッシュ・l / I / 1・rn / m を同一視。漢字やカナを写した注音符号・筆画文字は使えない |
| DoS | Workers Rate Limiting（参加試行数を IPv4 / IPv6 /64 ごと、および /48 ごと（/64 の 4 倍の枠を /64 の判定の後に消費するため、1 つの /64 が同じ /48 の他の利用者を締め出すことはできない）に集計。上限超過の通知は 1 分に 3 回まで（/48 ごとにも上限）で、以降は即座に閉じる HTTP 429。形式が不正なルームコードも HTTP 400）、ネットワークごとの接続数、部屋数の上限（非公開部屋は全体の一部まで、ネットワークあたり 2 部屋、最後の 1 人が抜けた時点で閉じる）、すぐ抜けた参加は公開部屋の人数に数えない、メッセージサイズ・頻度制限、無通信接続の切断、Origin チェック。拒否した理由（混雑・接続数・試行回数など）は画面に表示。※多数の IP アドレスを使う分散型の攻撃はアプリ側の上限だけでは防げないため、本番運用では Cloudflare のレート制限ルール等の併用を推奨 |
| 配信 | `core.wasm` はハッシュ付きのファイル名で配信し、更新直後に新しい JS と古い wasm のキャッシュが組み合わさることを防止 |

回帰テスト: `core/tests/security.rs`, `netcode.rs`, `leaks.rs`, `sim_review.rs`（`npm test` で実行）。各テストは修正前のコードでは失敗することを確認済み。

## 開発

必要なもの: Rust (stable) + `wasm32-unknown-unknown` ターゲット, Node.js 22

```bash
rustup target add wasm32-unknown-unknown
npm ci
npm test          # Rust シミュレーションのテスト (ボットだけの試合が決着するか, セキュリティ回帰テストなど)
npm run dev       # http://localhost:5173
npm run build     # dist/ に出力
```

オンラインサーバーをローカルで動かす場合:

```bash
npm --prefix server ci
npm run server:dev                       # http://127.0.0.1:8787
# クライアントを ?server=ws://127.0.0.1:8787 付きで開く
```

デプロイ:
- GitHub Pages: `.github/workflows/pages.yml` が push 時にビルドして公開します（リポジトリ設定の Pages ソースを「GitHub Actions」にしてください）。
- Cloudflare: `npm run server:deploy`（`CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を環境変数で渡す）。
